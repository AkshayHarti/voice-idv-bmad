# Accessibility Review

Scope: `DESIGN.md` + `EXPERIENCE.md` (Halo spine, updated 2026-11-02) for a regulated
identity-verification product whose founding requirement is a full run completable by
voice + haptics with the screen unread. This round added: (a) repeated-line rotation
among approved variants (~12-word spoken lines, pause-shaping commas, browser TTS);
(b) a docked confirm card showing the captured image with Keep/Retake before the spoken
question; (c) recognition-tolerant confirmation. `.working/confirm-card-mock.html` does
not exist (no `.working/` directory at all), so code-level checks are unverifiable —
see Findings.

## Overall verdict

**Not shippable as specified.** The confirm card — the centerpiece of this round — is an
eyesight gate smuggled into a product whose founding promise is screen-unread completion.
The spines loudly declare "a blind keep/retake with no image is a bug" while shipping
the exact inverse bug: a blind user for whom the image *is* nothing gets no spoken
quality description, no non-visual review path, and no defined alt semantics. On top of
that, the spines never arbitrate browser TTS against screen-reader announcements (two
voices talking over each other), never say where focus goes when DOM nodes dock/retire
mid-run, and let variation rotation erode the predictability assistive-technology users
depend on. The Accessibility Floor reads as if the confirm card was designed first and
the floor was never re-checked against it. Fix the two criticals before anything else;
the highs are all one bad user test away from becoming criticals.

## Findings

- **[critical]** The confirm card is unreviewable non-visually: a screen-unread user is asked to Keep/Retake an image they cannot inspect, with no spoken quality description (sharp? all corners in? glare?), contradicting the founding requirement (EXPERIENCE.md Component Patterns Confirm card row; Voice-Camera Choreography "Lock is always shown, then announced"; Accessibility Floor "Full run completable by voice + haptics with the screen unread"). *Fix:* specify a mandatory spoken + text quality verdict before the keep/retake question (e.g. "Front captured: sharp, all four corners visible, no glare. Keep it, or retake?"), derived from the same telemetry that drives coaching; a keep/retake with no non-visual quality statement is a bug, same weight as the blind-keep bug.
- **[critical]** No TTS / screen-reader arbitration: browser synthesis speaks the line while `aria-live` regions announce the same (or competing) updates, so SR users hear doubled or overlapping speech with no stated strategy (EXPERIENCE.md Voice and Tone "the engine stays browser synthesis"; Accessibility Floor Screen reader row). *Fix:* specify one coherent policy — e.g. the spoken-line text twin IS the live region (single source, `aria-live="polite"`), TTS and SR never fed duplicate strings, and a "screen reader detected → suppress self-voicing TTS in favor of SR announcements" rule or an explicit user toggle; test with VoiceOver + TalkBack with TTS on.
- **[high]** Captured-image alt semantics unspecified: decorative `alt=""` with the caption carrying meaning, or informative alt carrying quality state — the spines say neither, inviting either double-announcement (alt duplicates caption) or a silent image (DESIGN.md Confirm card "one-line spoken-twin caption"; EXPERIENCE.md Confirm card row). *Fix:* pin it down: image `alt=""` (decorative) + a real caption element holding the quality verdict; or informative alt ONLY if no visible caption duplicates it. Never a filename/framestamp as alt.
- **[high]** Live-region politeness for the confirm card unspecified: the Floor assigns polite to coach-card updates and assertive to the verdict, but the confirm card — a blocking question with a retire-on-answer lifecycle — gets no level, and its arrival races the per-Turn spoken-line update (EXPERIENCE.md Accessibility Floor; Component Patterns Spoken line row). *Fix:* assertive (or `role="alertdialog"` semantics with labeled context) for confirm-card arrival since it demands an answer and retires; document ordering vs the spoken-line update so SR users never hear the question before the quality verdict.
- **[high]** Focus management across docking/appear/retire is unspecified while DOM nodes move mid-run: the frame node "moves to the dock zone," coach cards replace, the confirm card appears then "never persists" — every one of these can drop focus to `<body>`, and "focus order follows reading order" is contradicted by reordered DOM (EXPERIENCE.md Component Patterns Capture frame + Coach card + Confirm card rows; Accessibility Floor "focus order follows reading order"). *Fix:* specify: focus moves to the confirm card heading (or Keep button) on appearance; on keep/retake focus returns to a named target (spoken-line region or next coach card); frame docking never moves the focused element; retiring a focused node moves focus before removal. Test with keyboard only, SR off.
- **[high]** Keep/Retake accessible names lack stage context: the same bare "Keep" / "Retake" repeats across doc-front, doc-back, challenge, and selfie stages, so SR and voice-control users hear/see an unlabeled choice out of context (EXPERIENCE.md Confirm card row; Interaction Primitives retake rule). *Fix:* accessible names carry the capture: "Keep document front" / "Retake document front" (via `aria-label` or visually-hidden context); visible text may stay short.
- **[high]** Variation rotation breaks the predictability AT users rely on: rotating surface variants mean the transcript holds N phrasings for one meaning (unsearchable, inconsistent identification per WCAG 3.2.4 spirit), and voice-control / switch users cannot learn one stable phrase per situation; recognition tolerance fixes input but the spines celebrate unpredictable output (EXPERIENCE.md Variation policy; Inspiration "repeats rotate among approved surface variants"). *Fix:* exempt functional prompts (consent, keep/retake, abort) from rotation — fixed wording there — and cap rotation to coaching color; document that meaning-identical lines share one transcript tag/label so SR search still works.
- **[medium]** Near-miss resolution has no confirmation echo: "kep it" resolves to Keep, but the spines never say the resolution is announced, so a mis-resolved utterance silently acts — and the transcript rule doesn't say whether heard-form, resolved-form, or both are recorded (EXPERIENCE.md Interaction Primitives "recognition-tolerant"). *Fix:* always echo the resolution in the spoken twin + text ("Keeping the front.") and record `heard → resolved` in the transcript; low-confidence near-misses re-ask instead of resolving.
- **[medium]** Reduced-motion docking unspecified: docking "animates opacity/position" and "scrolls into view," but the reduced-motion rules cover only glow/flash/transitions — smooth scroll + animated dock on every stage is a vestibular hit the Floor forgot (DESIGN.md Capture frame; EXPERIENCE.md Component Patterns Capture frame row; Accessibility Floor Reduced motion row). *Fix:* under `prefers-reduced-motion`, docking is instant (no smooth scroll — `behavior: "instant"`, no opacity/position animation); state change still announced via live region + haptic.
- **[medium]** `.working/confirm-card-mock.html` does not exist, so alt text, live regions, focus order, and button labeling cannot be verified at code level despite being in scope for this round. *Fix:* land the mock, then verify: image alt per this review, one assertive arrival announcement, focus-into-card on appear with focus-restore on retire, context-carrying button names, ≥44pt targets with ≥8px gaps, and full keyboard operability.
- **[medium]** The 10s silence re-ask can fire while a screen reader is still announcing: SR output takes longer than TTS, and neither the timeout nor the re-ask accounts for SR latency (EXPERIENCE.md State Patterns Listening row). *Fix:* extend/suppress the silence timer while SR announcements are pending where detectable; at minimum document that the re-ask must not interrupt an in-progress announcement and must itself be polite-queued.
- **[medium]** Coach-card diagram slot has no text-equivalent rule: the optional spatial diagram (tilt, thumb, corners) is exactly the kind of image-only instruction a screen-unread user cannot use, and the Generated panel text-equivalent rule doesn't cover coach cards (EXPERIENCE.md Component Patterns Coach card row; DESIGN.md Coach card). *Fix:* every diagram ships with a text twin at least as specific as the visual ("your thumb covers the bottom-right corner") — or the diagram slot is decorative-only by contract and the imperative alone must suffice.
- **[medium]** Tap-to-mute can kill the founding channel with no stated caption backstop: muting the orb silences speech, and while captions promise "every spoken line appears as text," the spines never say a muted run still renders those lines (nothing is technically "spoken") — leaving mute + screen-unread as a dead end (EXPERIENCE.md Component Patterns Voice orb row; Accessibility Floor Captions row). *Fix:* specify that mute changes audio output only — text twins and live-region announcements continue unchanged — and that mute state itself is announced and captioned ("Muted. Captions continue.").
- **[medium]** Lock signal may be color-only in the static visual: guides flip blue→green with a flash (held solid under reduced motion), but no shape/label change is specified, so low-vision and colorblind users get hue as the only visual delta (DESIGN.md Capture frame; EXPERIENCE.md State Patterns Capturing row). *Fix:* pair the color change with a shape or label change (e.g. brackets gain check-ticks, `capturing…` meta flips to `locked`), and keep the spoken + haptic lock signal unconditional.
- **[low]** Pause-shaping commas leak into SR/braille twins: commas tuned for TTS prosody will be honored (or stumbled over) by screen readers and braille displays reading the same text twin, and the ~12-word cap is a TTS rule imposed on text without checking SR readability (EXPERIENCE.md Voice and Tone "Speech shaping"). *Fix:* accept the commas but verify with at least one SR + braille pass that shaped lines read cleanly; allow the text twin to differ in punctuation from the TTS string if SR testing demands it.
- **[low]** Barge-in marking has no announcement rule: interruption "stops synthesis immediately and the partial line is marked" — but marked how, and is the mark announced or silently visual? (EXPERIENCE.md Interaction Primitives; Component Patterns Transcript turn row). *Fix:* specify a polite live-region note ("Interrupted.") plus a transcript marker with an accessible label, not a color/tick-only cue.
- **[low]** Tap-target spacing and orb size underspecified: "≥44pt" with no inter-target gap (WCAG 2.5.8 wants 24px/8px minimum spacing), and the orb — a mute toggle — has no size at all; the Keep/Retake pair squeezed into a docked card above the input is exactly where cramped targets happen (EXPERIENCE.md Accessibility Floor; DESIGN.md Voice orb). *Fix:* add minimum 8px gaps between Keep/Retake and the input row, size the orb ≥44pt, and give the long-press-reserved function a documented accessible path.
- **[low]** The confirm-card image has no transcript standing: the transcript is "the accessible record," but the spines never say whether the confirm step leaves a transcript turn (quality verdict + keep/retake + image reference/dev-local note) or vanishes with the retired card (EXPERIENCE.md Component Patterns Transcript turn row; Confirm card "retires on keep/retake"). *Fix:* log one transcript turn per confirm step — capture name, quality verdict, decision — so the accessible record survives the card's retirement.
